# 标注规范

> 版本 **1.0**（2026-11-21 初版）
> 数据格式：`data/labels.jsonl`（一行一张图）
> 示例：`data/labels.example.jsonl`
> 校验命令：`python tools/check_contract.py --labels data/labels.jsonl`

---

## 1. 先说清楚：标注不是用来训练模型的

这个比赛**不要求自训模型**，而且现场赛只允许使用阿里云百炼平台提供的模型能力，
「允许使用不含模型能力的通用开源库」——自己训一个裂缝分割模型，现场用不了，
属于白干（还有合规风险）。

那标注有什么用？**用来量出"改了提示词之后，到底是变好还是变坏"。**

- 没有标注：每次改提示词只能靠肉眼看一张图，"感觉好像准了点"——无法收敛。
- 有标注：跑一遍脚本，得到"框对上了几个、类型错了几个、误报了几个"，
  改动前后两组数字一对比，好坏立刻见分晓。

所以这份数据的目标是**回归测试集**，不是训练集。数量不用大，**覆盖要全**。

## 2. 文件与格式

```
data/
├── images/                 # 原图（文件名就是 image_id，不含扩展名）
│   ├── mural_001.png
│   └── mural_002.jpg
├── labels.jsonl            # 标注文件，一行一张图（UTF-8，无 BOM）
└── labels.example.jsonl    # 格式示例，不要往里添数据
```

`labels.jsonl` 一行一条，字段如下：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `image_id` | ✅ | str | 文件名去掉扩展名，和 `data/images/` 里的文件一一对应 |
| `source` | ✅ | str | 来源。写「命题方提供」或具体 URL，必须能追溯 |
| `license` | ✅ | str | 授权说明。写「仅限本次比赛使用」也可以，但不能空 |
| `width` / `height` | ✅ | int | 原图像素尺寸，用来核对归一化坐标 |
| `negative` | ✅ | bool | `true` = 这张图没有需要标记的病害 |
| `annotator` | 建议 | str | 标注人姓名 |
| `regions` | ✅ | list | 0–3 个区域；`negative=true` 时必须为空 |

`regions` 里每个区域：

| 字段 | 类型 | 说明 |
|---|---|---|
| `bbox` | `[x1,y1,x2,y2]` | **归一化到 0–1**，原点左上角 |
| `disease` | 8 类枚举 | 只用这 8 个名字，别名会被脚本自动收敛 |
| `severity` | 轻/中/重 | 严重程度 |
| `note` | str ≤40 字 | 一句话备注，给自己看 |
| `rank` | int 1–3 | 重要程度排序，1 最重要，不能重复 |

## 3. 标什么：只标 1–3 个最值得关注的区域

**不要标全 8 类。**

理由很直接：交付物是「在原图上标出 1–3 处值得关注的区域」。
标了 8 类，评测时你没法回答"这次改完提示词，卡片上的那 3 个位置选对了没有"——
因为标准答案本身就有 8 个。

一张图里确实可能出现多种病害，这时候按下面的顺序取前 3 个：

1. **对画面内容的威胁**：遮住/割裂了人物、衣纹、纹样主体的优先
2. **面积**：同样威胁下，范围大的优先
3. **证据强度**：前两项接近时，肉眼一眼能看出来的优先

> 一张图只标得出 1 个，就只标 1 个。凑数是这份数据最常见的污染源。

## 4. 病害判据速查（视觉层面，不是专业鉴定标准）

这份表只解决一个问题：**看到什么才算这一类**。它不用于给文物下结论。

| 类型 | 视觉上找什么 | 最容易混成什么 |
|---|---|---|
| 裂隙 | 线状、连续、常分叉；**不受绘画轮廓约束**，会横穿不同色块 | 衣纹勾线、装饰线描 |
| 起甲 | 颜料层边缘翘起；侧光下有亮边或投影，局部浮起 | 高光反光、描白边 |
| 颜料层脱落 | 边界锐利的缺块，露出下层白/灰/土色 | 原绘白粉、画面留白 |
| 酥碱 | 白色盐霜结晶、鼓包、泡状起壳、酥松颗粒感 | 粉化、积尘、霉斑 |
| 粉化 | 表面失去粘结、呈粉状；颜色发灰变淡、无光泽 | 褪色、积尘 |
| 水渍 | 边缘有渍线（像水位线）、流挂痕、深浅交界的轮廓 | 原绘底色不均、烟熏 |
| 变色或褪色 | 与同窟同期图像比发白/发暗/偏色 | 原绘色彩层次、拍摄白平衡 |
| 地仗层脱落 | 露出粗颗粒泥层、草秸、砂砾，甚至支撑体 | 颜料层脱落（区别只在"掉了多深"） |

判断不了就先不标，写进 `note`。**宁可少标，不要错标**——
错标会把评测分数拉偏，比不标更糟。

## 5. 框怎么画

- **贴紧病害的可见范围**，最多外扩 5–10% 当过渡带。
- **不要为了保险把框画到半个画面。** 评测用的是框的重叠度（IoU）：
  人工标一个很大的框，模型给出一个精确的小框，重叠度会低到 0.3 以下，
  系统会认为"没找到"——等于白标。
- 框**不要跨出画面边界**。
- 一张图里多个框尽量**不重叠**；两个框大面积重叠说明是同一处病害，合并成一个。
- 坐标是**归一化**的：`x1 = 左边界像素 / 图宽`，`y1 = 上边界像素 / 图高`。
  不要填像素值。

## 6. 负样本（这一类最容易漏，但最重要）

**单独准备 20 张"没有可标病害"的图**，`negative: true`。

- 完好的壁画局部
- 纯纹样、装饰图案、几何边饰
- 人物轮廓、衣纹线条密集的区域
- 拍虚了、过曝了的图（也算负样本，因为正确答案是"看不出来"）

为什么必须有：提示词里自己都写了「不要把壁画原有的绘画纹样、人物轮廓误判为病害」。
误报恰恰是最丢「问题理解」分的地方——评委看到卡上把一朵莲花圈成"颜料层脱落"，
后面写得再好也没用了。

对应到代码：`Observation.findings` 允许为空，就是为了让 A 能说"没看出问题"。

## 7. 分层要求（回归集怎么配比）

30 张图左右，按下表配比，别全挑同一种病害：

| 类别 | 最低数量 | 备注 |
|---|---|---|
| 裂隙 | 5 | 最容易识别的，作为基线 |
| 颜料层脱落 / 地仗层脱落 | 各 3 | 两者容易混，必须都有 |
| 起甲 / 酥碱 / 粉化 | 各 3 | 依赖侧光，多数图会标"看不了" |
| 水渍 / 变色或褪色 | 各 3 | 主观性强，靠注释说清依据 |
| 负样本 | 20 | 见上一节 |
| 变体 | 5 | 见下 |

**变体那 5 张**：从已有图里裁切、旋转、调亮度，或者用手机翻拍屏幕。
目的是防一件事——测试图如果是网上很有名的壁画，模型可能"认得"这张图，
表现得比真实场景好。变体图它认不出来，测的才是真本事。

## 8. 验收标准

标完跑一条命令：

```bash
python tools/check_contract.py --labels data/labels.jsonl
```

全部通过的标准：

- [ ] 0 条解析失败
- [ ] 0 条 `image_id` 在 `data/images/` 里找不到对应文件
- [ ] 8 类病害每类至少 3 张
- [ ] 负样本 ≥ 20 张
- [ ] 每张正样本 1–3 个框，`rank` 不重复
- [ ] 抽查 5 张：框是否贴边、`disease` 是否在白名单里

脚本会把类别分布、负样本数、框的平均面积占比打出来。
平均面积占比如果超过 0.6，基本可以断定框画大了，回去返工。

---

## 9. 一条最重要的约定

**标注格式和卡片契约是同一套坐标、同一套病害名。**

- 坐标都是归一化 0–1、原点左上；
- 病害名都来自 `src/schemas.py` 里的同一份白名单。

这样模型输出、人工标注、卡片渲染三方才能直接对比，不需要任何换算。
如果在标注里自创一个病害名，评测脚本会直接报错——那不是脚本太严，是接口被绕过了。
