# mural · AI 壁画观察卡

## 网页工作台

在仓库根目录运行 `python server.py`，打开 `http://127.0.0.1:8000`。网页可上传或更换图片、调用现有的观察→审查→成稿流水线、人工调整关注区域及文字，并在确认复核后通过浏览器打印或另存为 PDF。运行前须按下文配置 `.env`。如果模型没有生成可确认的关注区域，网页会提示人工检查，仍可手动标记。正式提交前请核对打印预览、图片授权和人工复核内容。


一张壁画照片进去，一页 AI 观察卡 PDF 出来。

流程是三个环节：**观察 → 审查 → 成稿**。观察环节找出值得关注的区域并标框；
审查环节看着原图逐条复核、砍掉证据不足的；成稿环节写总述、保护建议和风险；
最后渲染成一页 A4。

> 本文档写给所有人看，代码和任务都不写姓名，按**角色**认领。
> 一个人可以兼多个角色。

## 现在的状态

- **能跑**：单张图 → 观察（8–10 个带框候选）→ 审查（逐条分级、筛选展示项）→ 成稿（建议 + 风险）→ **一页 A4 PDF**
- **还没做**：完整标注集、回归评测、客户端硬化（大图缩放 / 网络重试）、公开部署所需的访问控制
- **别训模型**：现场赛只认百炼平台的模型能力，自训模型用不上

初检少于八处时，A 会用原图和大面积同类父框的局部放大图补查。每个子区都要有自己的坐标和观察依据，拆分后只计子区。补查仍不足八处会保存候选并提示不足。初检和补查可在 `output/observations` 与 `output/raw` 追溯。
B 逐条给出高、中、低评级；低档标记「人工复核」，高、中档由系统完成当前数字观察判定。每种「类型、等级」组合最多上卡一次，优先覆盖病种，其次覆盖等级。若仅有一至两种组合，按实际数出卡。`output/reviews/*.applied.json` 记录所有候选分级以及对应的上卡编号。

一次运行的产物：

| 目录 | 内容 |
|---|---|
| `output/raw/` | 模型原始回复（每次尝试一份，出问题先看这里） |
| `output/observations/` | 观察环节的候选区域 |
| `output/reviews/` | 审查环节的逐条裁决（含理由和复核点） |
| `output/cards/` | `card.json` + 一页观察卡 `card.pdf`（同名 `.png` 是预览图） |
| `output/trace/` | 运行日志，一行一个事件 |

跑一张图：

```bash
python main.py                                            # 自动用 data/images 下第一张
python main.py data/images/你的图.png
python main.py --source "命题方提供的比赛材料" --license "仅限本次比赛使用"
```

两个实测数字（**在 qwen3.8-max 上测的**，同一张 1123×756 的壁画；换模型后没有重测）：

| | 耗时 | 输出 token | 候选数 |
|---|---|---|---|
| 思考链开着 | 109 秒 | 4955 | 1 个 |
| 思考链关掉 | 13 秒 | 675 | 4 个 |

所以默认关闭思考链。这个任务要的是"把看到的说清楚"，不需要长链推理。
运行日志里的 `thinking` 字段记的是**实际关没关**（`off` / `on`），
不是"有没有发参数"——早先那个字段名容易让人反过来理解。

## R2 · 数据标注：要求与提示

### 先理解这件事的目的

**标注不是为了训练模型**（现场赛不允许自训模型），是为了量出"改了提示词之后到底变好还是变坏"。

- 没有标注：每次改提示词只能肉眼看一张图，"感觉好像准了"——没法收敛。
- 有标注：跑一遍脚本，得到"框对上几个、类型错几个、误报几个"，两组数字一对比就知道好坏。

所以这是**回归测试集**，不是训练集。数量不用大，**覆盖要全**。

### 数量与配比

| 类别 | 最低数量 |
|---|---|
| 裂隙 | 5 |
| 颜料层脱落 / 地仗层脱落 | 各 3 |
| 起甲 / 酥碱 / 粉化 | 各 3 |
| 水渍 / 变色或褪色 | 各 3 |
| **负样本**（无病害、纯纹样、装饰图案） | **20** |
| 变体（裁切、旋转、调亮度、手机翻拍） | 5 |

合计约 30 张正样本 + 20 张负样本。

**负样本最重要，也最容易漏。** 卡片上把一朵莲花纹样圈成"颜料层脱落"，比漏掉一处真病害更糟——
评委一眼就能看穿，后面写得再好也没用。

### 格式

一行一张图，写在 `data/labels.jsonl`（UTF-8，无 BOM）：

```json
{"image_id": "mural_001", "source": "命题方提供", "license": "仅限本次比赛使用",
 "width": 1123, "height": 756, "negative": false, "annotator": "R2",
 "regions": [{"bbox": [0.02, 0.03, 0.98, 0.96], "disease": "裂隙",
              "severity": "重", "note": "网状龟裂贯穿全图", "rank": 1}]}
```

完整字段说明见 [docs/annotation.md](docs/annotation.md)，可用的三条样例见
[data/labels.example.jsonl](data/labels.example.jsonl)。

### 五条最容易错的地方

1. **只标 1–3 个最值得关注的区域，不要标全 8 类。**
   交付物是"在原图上标出 1–3 处"，标 8 个就没法回答"这次改动有没有选对那 3 个"。
2. **框贴紧病害的可见范围，最多外扩 5–10%。**
   不要"为了保险"画到半个画面——评测用的是框的重叠度，框太松会把模型精确的框判成没找到。
3. **病害名只能从 8 个名字里选**：
   裂隙、起甲、颜料层脱落、酥碱、粉化、水渍、变色或褪色、地仗层脱落。
   自创名字会让校验直接报错。
4. **负样本不能有框，正样本不能没框；看不清的填 `assessment="无法判断"`，不要当负样本。**
5. **坐标是归一化的 0–1**（`左边界像素 ÷ 图宽`），不是像素值。

### 验收：一条命令

```bash
python tools/check_contract.py --labels data/labels.jsonl
```

全部通过的标准：

- [ ] 0 条解析失败
- [ ] 8 类病害每类至少 3 张
- [ ] 负样本 ≥ 20 张
- [ ] 每张正样本 1–3 个框，`rank` 不重复
- [ ] 框平均面积占比不超过 60%（超过基本可以断定画大了）

### 几条提速提示

- 先把 `docs/annotation.md` 第 4 节的"判据速查"过一遍，再开始标，能省掉大量返工。
- 一张图看不出明确病害时，**直接标负样本**，不要勉强凑一个。
- 判断不了就先不标，在 `note` 里写一句话。**宁可少标，不要错标**——错标会把评测分数拉偏，比不标更糟。
- 每标完 10 张就跑一次校验，不要攒到最后一起报错。
- 命题方正式材料只有 2–3 张，现在的图都是自己找的**练手用**，`source` 栏写清楚来源即可。

## R3 · 版式与视频：任务与要求

### 1. 一页观察卡版式

输入：[docs/card.example.json](docs/card.example.json)（已经填满所有字数上限）

要求：

- A4 单页，**绝对不能出第二页**（规则：超过 1 页只评第 1 页）
- 缩略图上要能看清 1–3 个彩色框，框上的编号要和正文的 R1/R2/R3 对应
- 必须包含：总述 / 区域说明（观察 + 影响 + 复核点）/ 建议（含依据和风险）/ 不确定性 / AI 生成与人工复核的区分 / 图片与工具来源
- 示例卡能排下，真实数据就都能排下——**用示例卡测版式，不要用随手找的短文测试**

交付：一版 PDF 或图片 + 一句"最长的字段排第几行"的说明。

### 2. 120 秒演示视频

规则：**超过 2 分钟只评前 2 分钟**。建议分段：

| 时间 | 画面 | 目的 |
|---|---|---|
| 0–25s | 原图 + 一句话背景，人工指出可疑区域 | 交代场景，证明不是凭空生成 |
| 25–70s | 观察环节出候选 → 审查环节砍掉一条 | 展示"AI 会自己纠错" |
| 70–100s | 一页卡生成，框、说明、建议、风险都在 | 展示结果 |
| 100–120s | 人工复核：哪条保留、哪条打回、为什么 | **最重要的一段**，点题"人机协同" |

要求：

- 视频里出现的工具、模型，必须是现场赛能复现的（只用百炼 / 千问办公，不要出现中转站、其他 AI 助手）
- 结论必须和观察卡一致——评委两边对着看
- 演示用的那次运行要留下 `output/trace/` 日志，能对上

交付：成片（≤2 分钟）+ 一份分镜文字稿。

### 3.（可并入 R2）负样本收集

20 张"没有可标病害"的图：完好壁画局部、纯纹样、装饰图案、拍虚或过曝的图。
要求同 R2 的负样本规则。

## R4 · 报告与合规：任务与要求

### 1. 来源与工具披露清单

这是**独立评分维度**，而且"隐瞒第三方 AI 工具"是取消成绩级别的问题，所以必须提前收，不能最后补。

需要一张表，逐项列：

| 项目 | 内容 |
|---|---|
| 每张图的来源 | 命题方提供 / 具体 URL / 自摄 |
| 每张图的授权 | 授权范围、是否可以公开使用 |
| 使用的模型 | 准确全名（如 `qwen3.8-max`），不要写简称或记错 |
| 使用的平台 | 阿里云百炼（DashScope） |
| 其他工具 | 开源库也要写（如 Pillow、Python 版本） |
| 提示词版本 | 卡片上有自动记录，照抄即可 |

### 2. 报告正文

要覆盖：

- 问题理解：这个赛题到底要解决什么、AI 的边界在哪里
- 方法：为什么是"观察 → 审查 → 成稿"三步，而不是一次性让模型输出
- 建议与依据：卡片上每条建议的依据和风险从哪来（来自处置原则表）
- 不确定性与人工复核：哪些内容必须人看过才能用
- 合规：来源、授权、工具披露

### 3. 答辩 PPT（现场用，建议 ≤10 页）

现场有 30 分钟（15 分钟讲 + 15 分钟问答）。要能回答三个问题：

- 你们的 AI 在哪一步做了什么、哪一步没做（边界）
- 凭什么相信输出不是编的（裁决记录 + 日志）
- 哪些地方必须人来判断（复核点）

## 常见问题

**Q：我标的框和模型输出的框对不上怎么办？**
不用管。评测脚本会自动算重叠度，人标的和模型给的是两套独立的框，不需要手动对齐。

**Q：一张图里我看出 5 处问题，只能标 3 个？**
对。按"对画面内容的威胁"排序取前 3：遮住或割裂了人物、衣纹、纹样主体的优先；同样威胁下面积大的优先。

**Q：视频里能不能快进？**
可以，但要标注"已加速"，不要让人误以为实时。真实耗时日志在旁边备着即可。

**Q：代码跑不起来？**
先确认用的是 Anaconda 环境（不是项目里那个空的 `.venv`），然后看报错里的路径；
还不行把报错原文发群里，不要只说"跑不起来"。
